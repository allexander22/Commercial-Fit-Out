# commercialfitout.co.uk

Marketing website for **A2 Commercial Fit Out LTD**, built as a static Astro site and deployed to GitHub Pages.

## Overview

- Framework: [Astro](https://astro.build) v5, `output: 'static'`
- Styling: hand-written global CSS tokens + Astro scoped `<style>` per component — no CSS framework
- Content: Astro Content Collections (Markdown + zod schemas) for sectors, locations, case studies and insights articles
- Images: `astro:assets` with Sharp — build-time AVIF/WebP generation
- Client JS: a single ~15-line mobile-nav toggle script; everything else (FAQ accordions, etc.) is plain HTML/CSS
- Hosting: GitHub Pages + custom domain, deployed via GitHub Actions (`withastro/action`)

## Prerequisites

- Node.js 22.x (LTS)
- npm

## Commands

| Command | Action |
|---|---|
| `npm install` | Install dependencies |
| `npm run dev` | Start local dev server |
| `npm run build` | Build the production site to `dist/` |
| `npm run preview` | Preview the production build locally |

On Windows, if `node`/`npm` aren't on your PATH, prefix commands with:
`$env:Path = "$env:LOCALAPPDATA\Programs\nodejs;$env:Path"; `

## Editing content

### Add a new case study

1. Create `src/content/caseStudies/<slug>.md` with frontmatter matching the schema in `src/content.config.ts` (`title`, `metaDescription`, `sector`, `location`, `sqFt`, `durationWeeks`, `outcome`, `placeholder`, `order`).
2. Write the body in Markdown — this becomes the page content below the facts panel.
3. Set `placeholder: false` once it's a real, verified project (this removes the "Example project" flag from the card and page).
4. The route `/projects/<slug>/` is generated automatically — no page file needed.

### Add a new insights article

Same pattern in `src/content/insights/<slug>.md`, with `title`, `metaDescription`, `publishDate` (YYYY-MM-DD), `summary`, `order`. Route: `/insights/<slug>/`.

### Add a sector or location page

Same pattern in `src/content/sectors/` or `src/content/locations/`. These also feed their respective hub pages (`/sectors/`, `/locations/`) automatically.

### Replace placeholder images

Real project photography should go in `src/assets/images/` and be imported directly into the relevant `.astro` page (Astro's `<Image>`/`<Picture>` components require a static import, not a runtime path). The placeholder images currently in that folder were generated by `scripts/generate-placeholders.mjs` — re-run `node scripts/generate-placeholders.mjs` any time you want to regenerate them, or simply overwrite the `.jpg` files with real photography of the same aspect ratio (16:9 for `hero.jpg`, 3:2 for the rest) and re-run the build.

### Logo

`src/components/Logo.astro` is a placeholder inline SVG wordmark. Replace its markup (or swap in an `<img>`/`<Image>` pointing at a real logo file) once final brand assets arrive.

### Contact form (Web3Forms)

The contact form on `/contact/` posts to Web3Forms but **will not deliver submissions until you add an access key**:

1. Go to [web3forms.com](https://web3forms.com) and enter an email address to receive submissions — no account signup required.
2. Copy the access key you're given.
3. In `src/pages/contact.astro`, replace `YOUR_WEB3FORMS_ACCESS_KEY` (the hidden `access_key` input value) with your real key.
4. Rebuild and redeploy.

Until this is done, the prominent `mailto:` link on the contact page (and in the header/footer) is the working fallback.

### Phone number

`PHONE` in `src/consts.ts` is currently an empty string, so phone links/labels are hidden site-wide. Once a business number is confirmed, set it there (e.g. `'01622 000000'`) and it will appear automatically in the header, footer and contact page.

## Deployment setup (first time)

1. Push this repository to GitHub (public or private with GitHub Pages available on your plan).
2. In the repo, go to **Settings → Pages** and set the source to **GitHub Actions**.
3. Push to `main` — the `.github/workflows/deploy.yml` workflow builds and deploys automatically via `withastro/action` + `actions/deploy-pages`.
4. Still under **Settings → Pages**, set the **custom domain** to `commercialfitout.co.uk` (this matches `public/CNAME`, which Astro copies into every build) and tick **Enforce HTTPS** once the certificate has provisioned (can take up to 24 hours after DNS is correct).
5. At your domain registrar/DNS provider, add:
   - Four apex `A` records for `commercialfitout.co.uk` pointing to:
     - `185.199.108.153`
     - `185.199.109.153`
     - `185.199.110.153`
     - `185.199.111.153`
   - Optionally, `AAAA` records for IPv6:
     - `2606:50c0:8000::153`
     - `2606:50c0:8001::153`
     - `2606:50c0:8002::153`
     - `2606:50c0:8003::153`
   - A `CNAME` record for `www` pointing to `<github-username-or-org>.github.io`
6. Verify the live site over HTTPS and check `www.commercialfitout.co.uk` redirects to the apex domain (GitHub Pages handles this once the custom domain is set and HTTPS is enforced).

## Known limitation: GitHub Pages can't send custom HTTP headers

GitHub Pages serves static files without letting you set response headers, so `X-Frame-Options` and HSTS preload can't be added directly. We mitigate this by delivering the Content-Security-Policy and Referrer-Policy via `<meta>` tags in `BaseLayout.astro` — since every asset on this site is self-hosted (no third-party scripts/fonts/embeds), a strict `script-src 'self'` policy works fine this way.

**Optional post-launch upgrade:** front the site with [Cloudflare](https://www.cloudflare.com) (free tier) to add proper response headers (`X-Frame-Options`, HSTS with preload, etc.) without changing hosting. Point Cloudflare at the same GitHub Pages origin and keep DNS records above pointed at Cloudflare instead of directly at GitHub once that's set up. Not required for launch.

## Analytics

No analytics are wired up at launch (avoids third-party JS and keeps the CSP simple). If needed later, [Cloudflare Web Analytics](https://www.cloudflare.com/web-analytics/) or [Plausible](https://plausible.io) are good options that don't require adding Google's JS to the page — either can be added as a single `<script>` tag in `BaseLayout.astro`, with the CSP's `script-src` updated to allow that one additional host.

## Out of scope for launch

Real project photography and case-study data, final logo files, phone number, Google Business Profile setup, Midlands location pages, analytics, and the Web3Forms access key — see `docs/IMPLEMENTATION_PLAN.md` for full context.
